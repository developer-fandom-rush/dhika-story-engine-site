# DHIKA Execution Failures and Guardrails

This file records recurring execution mistakes that must not repeat.

## Failure: not reading the rulebook
Guardrail: mandatory fresh-read of PROJECT_RULES + execution contract + writer continuity engine before substantial work.

## Failure: analysis becomes restriction
Symptom: “not established” is treated as “should not happen soon.”
Guardrail: describe current state; do not impose artificial pacing.

## Failure: visual-access reset
Symptom: future scene acts as if a previously seen body area is a first reveal.
Guardrail: consult Writer Continuity Engine visual-access ledger.

## Failure: pointer-only continuity
Symptom: Relationship History pointer is treated as sufficient context.
Guardrail: pointer = navigation only; read cumulative relationship state.

## Failure: over-justified prose
Symptom: story repeatedly explains why a gaze/outfit/tease is logical, acceptable or safe.
Guardrail: move analytical explanation to review tab; keep narrative immediate.

## Failure: summary destroys micro-beats
Symptom: causal sequence becomes “they flirted / tension increased.”
Guardrail: preserve the beat chain when duration, gaze, reaction or intent changes meaning.

## Failure: source intensity softened
Symptom: explicit source fact becomes vague “attention” or “boundary issue.”
Guardrail: use exact non-invented source meaning in analysis; do not sanitize material facts.

## Failure: future leakage
Guardrail: hard-stop each Part. Later facts cannot be imported backward.

## Failure: stale age warning
Guardrail: objective canon controls profile state. Chotu 19; Bantu/Bobby adult 18+.

## Failure: unrelated module regression
Guardrail: targeted patch isolation and pre-commit comparison.

## Failure: false GitHub disconnection
Guardrail: perform read-only connection test first; one path/operation failure does not mean GitHub is disconnected. Identify exact error and retry appropriately.
