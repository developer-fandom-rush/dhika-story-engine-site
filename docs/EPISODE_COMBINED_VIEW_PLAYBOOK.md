# DHIKA Episode Combined View Playbook

## Purpose

The combined Episode view is a navigation/aggregation layer. It must not rewrite approved Part content.

## Architecture

Each Part retains:
- 40/40 reading,
- Story + Images,
- Character Evolution,
- Relationship Progression,
- Reader Analysis,
- Relationship History Ledger,
- Storytelling & Authoring Notes.

Combined view links/embeds these approved modules.

## Preservation rule

Never rebuild a Part from memory when combining.
Fresh-read the native Part file.

## Current work protection

Story + Images under active image work must not be deleted/rebuilt unless explicitly requested.

## Cumulative state

Combined Episode summary must use:
- previous Episode end-state,
- Part deltas in order,
- Writer Continuity Engine.

## UI fidelity

Use approved Episode 01/02 architecture as reference.
Do not silently redesign CSS/layout.
Original and local reading must remain easy to compare; when line-level alignment is required, English/local line pairs stay in the same row.

## Hard-stop integrity

A combined view may show later Parts, but individual Part analysis must not gain future facts merely because they are visible elsewhere in the Episode.
